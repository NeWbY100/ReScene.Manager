# Multi-Set SRR Creation (Video Releases) — Design

**Date:** 2026-07-18 (rev 2, 2026-07-19 — addresses all 16 findings of the codex spec review)
**Status:** Design sections approved; Spec 1 of 2 — music releases are Spec 2.
**Reference implementation:** pyrescene (`E:\git\extern\pyrescene`). The verbatim excerpts in
`pyrescene-rules-excerpt.txt` (same directory) are **normative**: where this spec summarizes a rule
and the excerpt disagrees, the excerpt wins, and the port follows the excerpt's *sequential,
first-match* control flow. Deliberate divergences are labeled **[DIVERGENCE]**.

## Problem

Creating an SRR today accepts exactly one `.sfv` (or first `.rar`). Multi-set releases
(`DVD1/x.sfv`, `DVD2/x.sfv`) cannot be represented: adding the second set's SFV as a stored file
stores its *bytes* but writes no RAR volume headers for that set, so the second disc is
unreconstructable. The reading side (Reconstructor, Inspector) already fully supports multi-set
SRRs; creation is the missing half.

## Goal

Point the SRR Creator (Advanced tab and Create-an-SRR wizard) at a **release folder**. The app
scans it with pyrescene's classification rules, shows what it found, and writes one SRR covering
every RAR set plus samples (SRS), subtitle archives (nested SRR), proofs, and stored files. Output
follows pyReScene Auto conventions (relative forward-slash names, release-folder SRR name, same
block ordering); byte-level parity is asserted against golden fixtures generated by the local
pyrescene itself (§6). File input (single `.sfv`/`.rar`) keeps today's behavior byte-for-byte.

## Non-goals (Spec 2 and later)

- Music releases (mp3/flac/mp2 SFVs → per-track SRS). The scanner *detects* them (§2 rule M) and
  reports them unsupported; it never mis-creates.
- srrdb upload/compare integration.
- Compressed-RAR handling changes (existing behavior untouched).

## Architecture

| Layer | New responsibility |
|---|---|
| `ReScene.Lib` (`SRR/SRRWriter.cs`) | Format capability: write one SRR from N set inputs (N ≥ 0 when stored files exist), optionally with root-relative stored/volume names; one canonicalizer for all names (§1a). |
| `ReScene.App.Core` (`Services/ReleaseScanner.cs`, new) | Policy: classify a release directory via the ported pyrescene decision tree (§2). |
| `ReScene.App.Core` (`ViewModels/CreatorViewModel.cs`) | Folder input mode with generation-guarded scans (§3); route creation through the multi-input writer. |
| `ReScene.Manager` (Creator view + wizard body) | Chrome: "Browse folder…", detected-sets readout, status summary (§4). |

## 1. Lib — multi-input writer

```csharp
public Task<SRRCreationResult> CreateFromInputsAsync(
    string outputPath,
    IReadOnlyList<string> inputFiles,          // N ≥ 0; each .sfv or first-volume .rar
    string? rootFolder,                        // required when storeRelativePaths is true
    bool storeRelativePaths,                   // true → names relative to rootFolder ("CD1/x.sfv")
    IReadOnlyList<StoredFileEntry>? additionalFiles = null,
    SRRCreationOptions? options = null,
    CancellationToken ct = default);
```

- **Zero inputs is valid** when at least one stored file results (storage-only / fix-release SRR:
  header block + stored-file blocks, no volume blocks). Zero inputs AND zero stored files → error
  result (nothing to write). *(Review finding 1.)*
- Existing `CreateFromSFVAsync` delegates (single-item list, `storeRelativePaths: false`); existing
  single-**RAR** input flow likewise delegates and stays byte-identical — both guarded by the
  existing tests. *(Finding 12, file-mode half.)*
- Per input, in list order: `.sfv` → parse volume list; `.rar` → walk the volume chain. A `.rar`
  input that is not the first volume of its set → error result (pyrescene `ValueError` parity).
- Stored-file blocks: `additionalFiles` first (list order), then input SFVs not already present.
- OSO-hash blocks per existing options handling.
- **Transaction:** output written to a temp file **in the destination directory**
  (`<name>.srr.tmp-<random>`), atomically moved over the destination on success
  (`File.Move(overwrite: true)`). On any failure or cancellation the temp is deleted and a
  pre-existing destination file is left untouched. The writer rejects an `outputPath` equal to any
  input or stored source path (case-insensitive full-path compare). *(Finding 15, writer half.)*

### 1a. Name canonicalizer (single writer-boundary contract) *(Findings 10, 13)*

All stored-file and volume names pass through one canonicalizer:

- Source paths are resolved (`Path.GetFullPath`); with `storeRelativePaths`, every source MUST
  resolve under `rootFolder` (also resolved) — anything outside → error result naming the file.
  Symlinks/junctions are not followed out of the root (resolved path decides; a junction target
  outside the root is outside the root).
- Logical name = resolved path relative to root, separators normalized to `/`. SFV volume entries
  are interpreted with both separator kinds, stripped of any drive/root or `..` segments — an
  entry that escapes the SFV's own directory → error result (malicious/malformed SFV).
- Without `storeRelativePaths`: logical name = flat file name (today's behavior).
- **Collision policy:** two distinct sources mapping to one logical name → error result listing
  both sources. Duplicate identical sources are deduplicated silently (ordinal-ignore-case on the
  resolved path — documented Windows-first, consistent with the whole app).
- **Deterministic output:** the writer writes exactly in the order given (callers own ordering);
  the scanner's collections are all totally ordered (§2 ordering) so identical trees produce
  identical SRRs regardless of filesystem enumeration order.

## 2. App.Core — ReleaseScanner

```csharp
public sealed record ReleaseSetInput(string SfvOrRarPath, string RelativeName);
public sealed record ReleaseScanResult(
    IReadOnlyList<ReleaseSetInput> MainSets,
    IReadOnlyList<string> SampleFiles,
    IReadOnlyList<string> SubtitleSfvs,       // nested-SRR candidates (pyrescene extra_sfvs)
    IReadOnlyList<string> StoredFiles,
    IReadOnlyList<string> MusicSfvs,          // detected, unsupported until Spec 2
    IReadOnlyList<string> Warnings);

public interface IReleaseScanner
{
    ReleaseScanResult Scan(string releaseRoot, CancellationToken ct = default);
}
```

The classifier is a **line-for-line port of the normative excerpt** — an ordered decision tree with
first-match semantics, not a declarative rule set. *(Finding 3.)* Summary of the tree (excerpt
governs; each ported branch cites its excerpt lines in a comment):

**2a. Main-set selection (`remove_unwanted_sfvs`)** — for each `*.sfv` under the root, in order:

1. Name contains `vobsub`/`subtitle` and release name lacks `subpack|vobsub|subtitle|sub.pack` →
   **excluded**.
2. Name contains `subs`: if the music/multi-CD false-positive regex (`^000?-` or `cd\d`/`flac`) or
   a subs-flavored release name matches, **fall through to the remaining checks** (pyrescene's
   `pass` — the SFV is *not* yet accepted); otherwise → **excluded**. *(Finding 3's `pass` nuance.)*
3. Parent dir ∈ exact set {`subs`,`vobsubs`,`vobsub`,`subtitles`,`sub`,`czsubs`,`subpack`,
   `vobsubs-full`,`vobsubs-light`,`codec`,`codecs`,`cover`,`covers`} → **excluded**.
4. Parent dir ∈ {`proof`,`proofs`}: pyrescene's proof state machine, ported exactly — requires the
   SFV to list **exactly one entry**; a singleton entry not ending in lowercase `.rar` → excluded
   (proof); otherwise read the RAR's packed-file blocks where the **last** block's image-ness wins
   (`skip = True/False` reassignment); RAR5/`ValueError` → warning + excluded; missing proof RAR →
   warning + excluded. Only `ValueError` is caught — other I/O exceptions propagate to the
   per-item warning handler as **[DIVERGENCE: hardening]** (pyrescene would crash). *(Findings 4, 5.)*
5. Directory matches `.*Subs.?CD\d$` → **excluded**.
6. Parent dir *contains* `subpack` (release name doesn't) → **excluded**; same for `subfix`; same
   for `fix`. Substring checks, ordered after the exact-set rule. *(Finding 2.)*
7. Otherwise → **main set**.

**Rescue fallback** (excerpt tail): if zero SFVs survived, every SFV with >1 entry or with a
music-extension entry (`.mp3/.flac/.mp2`, case-sensitive `endswith` like pyrescene) is re-admitted.
**[DIVERGENCE]** re-admitted *music* SFVs go to `MusicSfvs` (Spec 2), not `MainSets`; re-admitted
multi-entry RAR SFVs become main sets as in pyrescene. Zero SFVs after rescue → warning
("might be missing an SFV file") + RAR-only discovery (2e).

**Excluded-SFV destinations** *(finding 2's destination question, from `generate_srr`)*: every
excluded SFV (rules 1-6) goes to `SubtitleSfvs` — pyrescene treats ALL `extra_sfvs` as nested-SRR
candidates — EXCEPT proof-linked SFVs (rule 4: SFV + its RAR → `StoredFiles`) and SFVs in a
`dirfix` subdir (skipped entirely, warning). The nested-SRR pipeline itself (existing wizard
step) also stores each subtitle SFV, preserving pyrescene's stored-SFV behavior.

**2b. Music detection** *(finding 6)*: an SFV among the main-set candidates whose entries contain a
music extension (`.mp3/.flac/.mp2`, pyrescene's case-sensitive `endswith`) → `MusicSfvs` +
warning. **Mixed releases** (video sets AND music SFVs): video sets are created; music SFVs are
reported unsupported; creation is NOT disabled. Only a release whose every candidate is music (or
empty after rescue) disables folder-mode creation. Empty/corrupt SFVs → warning, stored-only.

**2c. Samples (`get_sample_files`, both phases)** *(finding 7)*: phase 1 — files with
`FileType.VideoExtensions` = `.mp4 .m4v .avi .mkv .wmv .vob .m2ts .ts .mpeg .mpg .m2v .m2p`
whose path contains `sample` (case-insensitive) or with a same-name `.sfv` sibling; phase 2 —
remaining videos whose **basename appears in any SFV's entries** anywhere in the release.

**2d. Stored files (`get_proof_files` chain, exact port)** *(findings 8, 9)*: every `*.nfo`;
proof images: keyword-path images (path contains `proof`/`sample`/`cover`/`screenshots`/`compare`)
are accepted **before** `always_skip` runs (a `Proof/Folder.jpg` IS stored — excerpt ordering);
root images pass `always_skip` (exact predicates: space in basename, stem ending `folder`,
basename containing `albumartsmall`, basename starting `albumart_{`) then `store_rls_root`
(basename starting `00`/`01`/`001` → accept; else >100 KB AND similar-named to nfo/sfv/rars AND
not a fixed-resolution cover → accept; else skip + warning). Independent pass
`filter_proof_rar_files`: ANY `*.rar` under the root with `proof` in its path whose packed blocks
include an image → stored. `strip_zeros`/`similar_to_good_name`/`fixed_resolution_cover` ported
per the excerpt.

**2e. RAR-only discovery** *(finding 12)*: when no main-set SFVs exist, first-volume RARs
(`.rar` not preceded by another volume of the same chain, via the existing lib volume-naming
logic) found outside excluded dirs become `MainSets` entries (pyrescene `main_rars` path). Sets
found via SFV subsume their volumes (no double-discovery).

**Ordering** *(finding 13)*: every collection in `ReleaseScanResult` is sorted by natural sort
(numeric-aware ordinal-ignore-case) of the root-relative path. `Warnings` are sorted by the path
they concern. This plus §1a's writer determinism makes output byte-stable.

**Error contract** *(finding 14)*: scanner I/O failures are per-item warnings (item classified
stored-only when readable metadata suffices, otherwise skipped); enumeration failure of the root
itself → error result via a `Warnings`-only result with empty collections. The scanner takes a
`CancellationToken` and throws `OperationCanceledException` promptly.

## 3. App.Core — CreatorViewModel

- `InputPath` accepts a directory (`Directory.Exists`). New `BrowseInputFolderCommand`
  (`IFileDialogService.OpenFolderAsync`).
- **Scan lifecycle** *(finding 14)*: each directory input bumps a scan generation (the
  `InspectorViewModel._loadGeneration` house pattern), cancels the previous scan's CTS, runs
  `Scan` in `Task.Run`, and applies results on the UI thread ONLY if its generation is still
  current. `IsScanning` gates Create and re-input. Stale scans can never overwrite newer state.
- On results: populate `DetectedSets` (new read-only collection), `StoredFiles` (path-prefixed
  logical names), `ExtraSampleFiles`, `ExtraSubtitleSfvFiles`; status summary
  `"2 RAR sets · 1 sample · 4 stored files"` + warnings; music-only → error status, Create
  disabled for folder mode.
- **Output path** *(finding 15)*: the VM tracks whether `OutputPath` is auto-generated or
  user-edited (auto-generated values are replaced on re-scan; user edits are never clobbered —
  refines the existing blank-only convention). Default: `<releaseRoot parent>/<releaseRootName>.srr`
  built with `Path.Combine` on the normalized root (trailing separators trimmed; filesystem roots
  like `D:\` produce an error status instead of a name).
- **Generated artifacts** *(finding 11)*: SRS and nested-SRR outputs mirror pyrescene's working-dir
  layout — artifact logical name = root-relative source path with the extension swapped; when two
  sources share a base name (e.g. `CD1/Sample/x.mkv`, `CD2/Sample/x.mkv` — or pyrescene's
  `.mkv`/`.m2ts` case), the full source extension is kept (`x.mkv.srs`) exactly as the excerpt
  does. Remaining logical-name collisions → per-item error, item skipped with warning.
- Creation (folder mode): `CreateFromInputsAsync(outputPath, DetectedSets paths in order,
  releaseRoot, storeRelativePaths: true, storedFiles, options, ct)`. File mode: unchanged.
- `ISRRCreationService`/`SRRCreationService` gain the pass-through.

## 4. UI (ReScene.Manager)

Both surfaces (Advanced `CreatorView.axaml`, wizard `CreateSRRWizardBody.axaml` step "1 of 5"):

- "Browse folder…" beside "Browse"; the typeable box accepts either path kind.
- Read-only `DetectedSets` list (ItemsControl of `RelativeName`) under the input row, visible when
  a folder scan found sets; `FieldStatusLine` carries the summary/warnings; a busy indicator while
  `IsScanning`.
- Wizard: the samples/subs step ("Step 2 of 5") and stored-files step ("Step 3 of 5") show the
  pre-populated lists; all existing add/remove/reorder controls keep working. Manual edits persist
  until the input changes (re-scan replaces collections).

## 5. Error handling

| Case | Behavior |
|---|---|
| Zero main sets, storable files exist (fix release) | Storage-only SRR (§1 zero-input mode) + warning. |
| Nothing storable at all | Error status; Create disabled. |
| Music-only release | Error status naming Spec 2; Create disabled (folder mode). Mixed → §2b. |
| SFV references a missing volume | Error result naming the file; no partial output; existing destination preserved. |
| Non-first-volume `.rar` input | Error result (pyrescene `ValueError` parity). |
| Source outside root / SFV entry escaping its directory / logical-name collision | Error result naming the offender (§1a). |
| Output path equals an input/source | Error result (§1). |
| Scanner per-item I/O errors | Warning; scan continues (§2 error contract). |
| Unreadable/RAR5 proof RAR | Warning; SFV excluded from sets (proof), per §2a rule 4. |
| Scan superseded by newer input | Silently discarded (generation guard, §3). |

## 6. Testing

**Golden fixtures (non-circular oracle)** *(finding 16)*: a committed generator script
(`ReScene.Lib/ReScene.Tests/TestData/multiset/generate-golden.py` + README) builds synthetic
release trees (2-disc RAR sets via SRRTestDataBuilder-equivalent store-mode RARs + real SFVs +
nfo + Sample/ + Subs/ + junk files) and runs the **local pyrescene**
(`E:\git\extern\pyrescene\bin\pyrescene.py`) over them; the resulting `.srr` files are committed
as golden fixtures. Lib tests assert OUR `CreateFromInputsAsync` output is **byte-identical** to
the golden SRR for the same tree (app-name field normalized), which proves separators, stored
names, volume names, and block order in one stroke. The existing pyrescene 2-CD fixture stays as
a read-side regression anchor.

**Lib:** golden byte-equality (above); zero-input storage-only SRR; zero-input zero-file
rejection; single-SFV and single-RAR delegation byte-identical to pre-change output (existing
tests untouched); missing volume / non-first RAR / outside-root / SFV-escape / name-collision /
output-equals-input error paths; cancellation and failure leave a pre-seeded destination intact;
temp file cleaned up.

**Scanner:** one test per decision-tree branch and per finding: subpack release keeps vobsub SFVs;
`pass`-fallthrough (subs-named SFV under a `cover` dir is still excluded); exact-set vs substring
pardir rules; proof single-entry/lowercase-`.rar`/last-block-wins/RAR5/missing-RAR variants; `Subs/CD1`;
rescue fallback (multi-entry re-admission; music → `MusicSfvs`); mixed release policy; both sample
phases (incl. differently-located SFV reference); `always_skip` exact predicates + keyword-dir
bypass (`Proof/Folder.jpg` stored, root `Folder.jpg` skipped, `MyFolder.png` skipped,
`AlbumArtLarge` NOT skipped, `AlbumArt_{...}` skipped); `store_rls_root` 00/01-prefix + size +
similar-name + resolution branches; independent proof-RAR pass; RAR-only discovery; natural sort
incl. `cd10 > cd2` and case-only names; per-item I/O warning; cancellation.

**VM:** stub-scanner population; generation guard (reverse completion order — old scan result
discarded); `IsScanning` gates; auto vs user-edited output path across re-scans; music-only
disables Create; creation captures ordered multi-input call; artifact collision skip+warning.

**E2E (agent bridge):** drive both surfaces on a synthesized two-disc release folder; verify
detected-sets readout, pre-populated wizard steps, created SRR opens in the Inspector with both
sets and in the Reconstructor with both discs in the Set column.

**Review gates:** codex reviews this spec (done — rev 2 addresses its 16 findings), the
